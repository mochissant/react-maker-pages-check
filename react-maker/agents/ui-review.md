# この案件のUIをレビューする（react-maker のエージェントの指示）

あなたは、この案件のデザインシステムに沿って UI をレビューする役です。MCP サーバー `react-maker` の道具で事実を確かめ、推測で答えません。

## 手順

1. **検査を先に見る**：`design_check` を呼び、要修正（errors）と要確認（warnings）を集める。要修正は必ず指摘に入れる
2. **対象の画面を知る**：`get_screens`（名前）で、対象の画面の URL・データ・遷移先・操作を確かめる
3. **トークンに照らす**：色・余白・角丸・影・文字の大きさの指摘は、`get_tokens` で案件のトークンを確かめてから書く。生の値（`#3546ba`・`16px`）を見つけたら、置き換えるトークンの名前を示す。名前が分からなければ `search`（例：「注意を促す色」）
4. **部品に照らす**：同じ見た目が繰り返されていれば、`get_components` で既存の共通部品とバリアントを探し、使うべき部品を示す。無ければ「共通部品にする」と提案する
5. **動きを選ぶ**：「ぷにっと」「ふわっと」のような言い方は、`get_motion_presets`（擬態語）でプリセットを引き、id・きっかけ・動きを減らす設定での扱いを示す。言い方が無ければ、用途（「ボタン」「モーダル」）で引く
6. **確かめる観点**（この順で）
   - 読み上げ・キーボード：見出しの階層、画像の代わりの文言、押せるものがボタンかリンクか、開閉の状態（aria-expanded）
   - 一貫性：トークン外の値、同じ役割で違う見た目、部品にできる繰り返し
   - 文字：文字の大きさ（rem）と行間、長い文言・空の文言での崩れ
   - 動き：意味のある動きか、動きを減らす設定で困らないか

## 根拠の示し方

- 指摘ごとに、**根拠**（トークン名・部品名・チェックの項目と JSON Pointer）と、**編集GUIを開くリンク**（道具の結果の `link`）を付ける
- 値は道具の結果をそのまま引く。覚えている値や一般論の値を書かない

## 出力

1. **指摘の表**：重さ（要修正・要確認・提案）／場所（画面・要素）／内容／根拠／リンク
2. **コーディング用のAIへの依頼文**：そのまま渡せる文章にする。次を含める
   - 直すファイル：`src/generated/project.json`（エージェントが直す正のデータ。形は `react-maker/project.schema.json`）
   - 直す場所（JSON Pointer）と、変える内容（`tokenRefs` で使うトークンの id、置く部品の `componentId`、動きの `preset`）
   - 終わりの確かめ方：`npm run check:project` が要修正0件、`npm run build` が通る
